# Spec: แลกเงิน และการใช้จ่ายสกุลเงินต่างประเทศ

Status: ready-for-agent

## Problem Statement

ผู้ใช้เดินทางต่างประเทศหรือใช้จ่ายเป็นสกุลเงินอื่นบ่อยขึ้น แต่แอปตอนนี้มีข้อจำกัด

1. **รองรับแค่ THB/USD** หลายจุดในโค้ดเช็ก `currency == 'USD' ? 'USD' : 'THB'` ตรง ๆ และ `ExchangeRateService` ดึงได้แค่ USD/THB จึงสร้างกระเป๋าเงินสด JPY หรือ EUR ไม่ได้
2. **การแลกเงินปนอยู่กับการโอน** การแลกเงินต้องทำผ่าน `transfer` ที่มี `to_amount` ทำให้แยกไม่ออกว่ารายการไหนเป็นการโอนธรรมดาและรายการไหนเป็นการแลกเงิน และไม่เห็น rate ที่ได้จริง
3. **บันทึกรายจ่ายสกุลต่างประเทศไม่ได้** เวลารูดบัตร THB ที่ต่างประเทศ บันทึกได้แค่ยอดบาท ข้อมูลว่ายอดเดิมคือ ¥3,000 และ rate ที่บัตรคิดจริงหายไป

## Solution

- เพิ่มรายการสกุลเงินที่กำหนดไว้ล่วงหน้า และดึง rate อัตโนมัติได้ทุกสกุล
- เพิ่ม `TransactionType.exchange` ('แลกเงิน') เป็น type ที่ชัดเจน ใช้เมื่อสองบัญชีคนละสกุลเท่านั้น ส่วน `transfer` ใช้ได้เฉพาะสกุลเดียวกัน
- expense/income บันทึกยอดสกุลต่างประเทศเป็นข้อมูลประกอบได้ (`foreign_amount`, `foreign_currency`) โดยยอดหลักยังเป็นสกุลของบัญชี
- ใช้ widget กรอกสองสกุลตัวเดียวกัน (จ่าย / ได้ / rate) ทั้งในการแลกเงินและรายจ่ายสกุลต่างประเทศ

## User Stories

1. As a ผู้ใช้ที่เดินทาง, I want สร้างบัญชีเงินสดสกุล JPY/EUR/ฯลฯ ได้, so that ติดตามเงินสดต่างประเทศที่ถืออยู่ได้
2. As a ผู้ใช้, I want บัญชีสกุลต่างประเทศอัปเดต rate อัตโนมัติ, so that net worth ที่แปลงเป็น THB เป็นปัจจุบัน
3. As a ผู้ใช้, I want บันทึกการแลกเงินเป็นรายการ "แลกเงิน" แยกจากการโอน, so that ดูประวัติการแลกเงินได้ชัดเจน
4. As a ผู้ใช้, I want กรอกยอดจ่ายและยอดที่ได้ แล้วเห็น rate ที่คำนวณให้, so that เทียบ rate จากร้านแลกเงินแต่ละที่ได้
5. As a ผู้ใช้, I want กรอก rate แล้วให้แอปคำนวณยอดอีกฝั่งให้, so that ไม่ต้องคำนวณเองตอนดูป้ายร้านแลกเงิน
6. As a ผู้ใช้, I want การแลกเงินไม่นับเป็นรายรับหรือรายจ่าย, so that งบประมาณและสถิติไม่เพี้ยน
7. As a ผู้ใช้, I want เติมเงินเข้าพอร์ตหุ้น US เป็นรายการแลกเงิน, so that เห็น rate ที่ได้ตอนแลก THB เป็น USD
8. As a ผู้ใช้, I want รายการโอนข้ามสกุลเดิมถูกแปลงเป็น "แลกเงิน", so that ประวัติเป็นมาตรฐานเดียวกัน
9. As a ผู้ใช้ที่รูดบัตรในต่างประเทศ, I want บันทึกยอดสกุลต่างประเทศคู่กับยอดบาทที่ถูกตัด, so that รู้ rate จริงที่บัตรคิด (รวมค่าธรรมเนียม)
10. As a ผู้ใช้, I want แอปเติมยอดบาทโดยประมาณจาก rate ตลาดให้, so that บันทึกได้ทันทีแล้วค่อยมาแก้เป็นยอดจริงเมื่อรายการ post
11. As a ผู้ใช้ระหว่างทริป, I want ฟอร์มจำสกุลต่างประเทศล่าสุดที่ใช้, so that ไม่ต้องเลือกสกุลซ้ำทุกครั้ง
12. As a ผู้ใช้, I want เห็นยอดสกุลต่างประเทศในรายการ (เช่น "¥3,000 → ฿702"), so that จำได้ว่ารายการนั้นจ่ายไปเท่าไรจริง

## Implementation Decisions

### สกุลเงิน

- ขยาย `CurrencyUtils.currencies` เป็นรายการที่กำหนดไว้ล่วงหน้า: THB, USD, JPY, EUR, GBP, CNY, KRW, SGD (เพิ่มได้ทีหลัง) โดยแต่ละสกุลมี code, symbol, ชื่อ และจำนวนทศนิยม (JPY/KRW ไม่มีทศนิยม)
- เลิกเช็ก `'USD'` แบบ hard-code ในจุดที่แสดงหรือจัดรูปแบบยอดเงิน (`currencyCodeLabel`, `currencyAmountSuffix`, `transaction_amount_hero_card`, `transaction_list_item` ฯลฯ) ให้ใช้ `CurrencyUtils` แทน ยกเว้น logic ของพอร์ต US ที่ผูกกับ USD จริง
- `ExchangeRateService` เพิ่ม `fetchRateToThb(currency)` ส่วน `AccountProvider` เปลี่ยน `_refreshUsdExchangeRate` ให้อัปเดตบัญชีทุกสกุลที่ไม่ใช่ THB และเปิด `autoUpdateRate` โดยดึง rate ครั้งเดียวต่อสกุล

### `TransactionType.exchange`

- label 'แลกเงิน', `usesDestinationAccount = true`, `supportsCategory = false`, ไม่เป็น `isExpenseLike` จึงไม่นับในรายรับรายจ่าย งบประมาณ cash flow และสถิติรายรับรายจ่าย
- ยอดคงเหลือ: บัญชีต้นทาง −`amount` บัญชีปลายทาง +`to_amount` (ใช้คอลัมน์ `to_amount` เดิม)
- ใช้ได้เฉพาะเมื่อบัญชีต้นทางและปลายทางคนละสกุล ฟอร์มแสดงเฉพาะบัญชีปลายทางที่สกุลต่างจากต้นทาง
- `transfer`, `debtRepay`, `debtTransfer` ใช้ได้เฉพาะสกุลเดียวกัน ฟอร์มแสดงเฉพาะบัญชีปลายทางสกุลเดียวกัน
- ไม่เก็บ rate ลง DB เพราะคำนวณจาก `amount` / `to_amount` ได้เสมอ
- ไอคอนและสีในรายการเป็นของ `exchange` เอง ตาม `docs/design.md`

### พอร์ตหุ้น US

- การเติมเงิน THB เข้าพอร์ต US และถอน USD กลับเป็น THB เป็น `exchange`
- สร้าง migration แก้ `sync_transfer_portfolio_cash` ให้ทำงานกับ `exchange` แทน `transfer` สำหรับกรณีข้ามสกุล (ยังคงตรวจว่ายอด USD ต้องเป็นบวก)
- แก้ logic คำนวณเงินเข้าพอร์ตใน `AccountProvider` (ที่ใช้ `tx.toAmount` ราวบรรทัด 457) และ `statistics_net_worth_calculator` ให้นับ `exchange`

### Migration ข้อมูลเดิม

- migration เดียวกันแปลงรายการ `transfer` ที่ `account_id` และ `to_account_id` เป็นบัญชีคนละสกุลให้เป็น `type = 'exchange'`
- เพิ่มคอลัมน์ `foreign_amount numeric NULL` และ `foreign_currency text NULL` ใน `transactions` ทั้งสองคอลัมน์ต้อง null พร้อมกันหรือมีค่าพร้อมกัน (check constraint)
- apply ด้วย `supabase db push`

### widget กรอกสองสกุล (ใช้ร่วมกัน)

- มี 3 ช่อง: ยอดสกุล A / ยอดสกุล B / rate
- สองช่องที่ผู้ใช้แก้ล่าสุดเป็นค่าที่ผู้ใช้กำหนด ส่วนช่องที่สามคำนวณให้ (ปัดตามจำนวนทศนิยมของสกุลนั้น)
- แสดง rate เป็น "1 [สกุลต่างประเทศ] = x ฿" เสมอ ถ้าไม่มีฝั่งไหนเป็น THB ใช้ "1 [ต้นทาง] = x [ปลายทาง]"
- ใช้ทั้งในฟอร์ม `exchange` และฟอร์มรายจ่ายสกุลต่างประเทศ

### รายจ่ายหรือรายรับสกุลต่างประเทศ

- `AppTransaction` เพิ่ม `foreignAmount` และ `foreignCurrency` (nullable) ใช้กับ expense/income ทุกบัญชี
- ฟอร์มมีสวิตช์ "ชำระเป็นสกุลต่างประเทศ" ปิดไว้เป็นค่าเริ่มต้น เมื่อเปิดจะแสดงตัวเลือกสกุลและ widget กรอกสองสกุล โดยฝั่งหนึ่งเป็นยอดต่างประเทศ อีกฝั่งเป็นยอดที่ตัดบัญชี (`amount`)
- ตอนกรอกยอดต่างประเทศ ให้เติมยอดที่ตัดบัญชีโดยประมาณจาก rate ตลาดปัจจุบันไว้ก่อน แล้วผู้ใช้แก้เป็นยอดจริงเองได้ ไม่มีสถานะ pending
- ค่าธรรมเนียม FX รวมอยู่ใน `amount` ไม่แยกรายการ
- ตัวเลือกสกุลมีค่าเริ่มต้นเป็นสกุลต่างประเทศล่าสุดที่ใช้
- สกุลต่างประเทศต้องไม่ตรงกับสกุลของบัญชี
- `amount` ยังเป็นสกุลของบัญชีเสมอ ยอดคงเหลือ งบประมาณ และสถิติจึงไม่เปลี่ยน
- รายการแสดง "¥3,000 → ฿702"

### Export

- CSV export และ AI finance export ใส่ type `exchange`, `foreign_amount` และ `foreign_currency`

## Out of Scope

- recurring transaction, CSV import และ `credit_card_bill_service` ยังไม่รองรับสกุลต่างประเทศ
- สถานะ "ยอดประมาณการ" หรือการแจ้งเตือนให้กลับมาแก้ยอดจริง
- โหมดทริป
- แยกค่าธรรมเนียม FX เป็นรายการต่างหาก
- รับสกุลเงินที่ไม่อยู่ในรายการ
- สถิติที่แปลงด้วย rate ย้อนหลัง (ยังใช้ `account.exchangeRate` ปัจจุบันเหมือนเดิม)

## Further Notes
