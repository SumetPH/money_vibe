# Spec: ระบบบัญชีผู้ใช้ (Autofill, รหัสผ่าน, Google)

Status: ready-for-human

อ้างอิง: `GLOSSARY.md` (บัญชีผู้ใช้, ช่องทางเข้าสู่ระบบ), `docs/adr/0002-single-user-account-per-email.md`

## Problem Statement

ผู้ใช้เข้าสู่ระบบได้ทางเดียวคือรหัสผ่าน และฟอร์ม login/สมัครไม่ทำงานร่วมกับ password manager ทำให้ต้องพิมพ์อีเมลและรหัสผ่านเองทุกครั้ง ผู้ใช้ที่มีบัญชี Google อยากเข้าแอปด้วยปุ่มเดียว ในหน้าตั้งค่าก็ยังเปลี่ยนรหัสผ่านไม่ได้ และไม่มีที่ดูหรือจัดการว่าบัญชีผู้ใช้ของตนมีช่องทางเข้าสู่ระบบอะไรบ้าง ผู้ใช้ยังกังวลว่าถ้าใช้ Google กับรหัสผ่านสลับกัน จะเกิดบัญชีผู้ใช้ซ้ำและข้อมูลการเงินแยกเป็นสองชุด

## Solution

- ฟอร์ม login, สมัคร และเปลี่ยนรหัสผ่านรองรับ autofill และให้ password manager บันทึกรหัสหลัง login สำเร็จ
- เพิ่มปุ่ม "ดำเนินการต่อด้วย Google" บน Android, iOS และ Web ถ้ายังไม่มีบัญชีผู้ใช้จะสร้างให้ ถ้าอีเมลตรงกับบัญชีผู้ใช้เดิมจะเข้าบัญชีผู้ใช้เดิม
- อีเมลหนึ่งมีบัญชีผู้ใช้ได้บัญชีเดียว การสมัครด้วยรหัสผ่านต้องยืนยันอีเมลด้วยรหัส OTP และการสมัครด้วยอีเมลที่มีบัญชีผู้ใช้อยู่แล้วจะถูกปฏิเสธ
- หน้าตั้งค่ามีกลุ่ม "ช่องทางเข้าสู่ระบบ" สำหรับเปลี่ยนรหัสผ่าน ตั้งรหัสผ่าน (กรณีมีแค่ Google) เชื่อม Google และยกเลิกการเชื่อม Google
- มีคู่มือ setup สำหรับ Google Cloud และ Supabase

## User Stories

1. ในฐานะผู้ใช้ ฉันต้องการให้ password manager เติมอีเมลและรหัสผ่านในหน้า login ให้อัตโนมัติ เพื่อจะได้ไม่ต้องพิมพ์เอง
2. ในฐานะผู้ใช้ ฉันต้องการให้ระบบถามว่าจะบันทึกรหัสผ่านหลัง login สำเร็จ เพื่อครั้งหน้าจะได้เข้าได้เร็วขึ้น
3. ในฐานะผู้ใช้ใหม่ ฉันต้องการให้ password manager เสนอรหัสผ่านที่แข็งแรงตอนสมัคร เพื่อจะได้ไม่ต้องคิดรหัสเอง
4. ในฐานะผู้ใช้ ฉันต้องการให้ช่องรหัสผ่านใหม่ในหน้าเปลี่ยนรหัสผ่านทำงานกับ password manager เพื่อให้รหัสที่บันทึกไว้อัปเดตตาม
5. ในฐานะผู้ใช้ใหม่ ฉันต้องการสมัครด้วย Google โดยกดปุ่มเดียว เพื่อจะได้ไม่ต้องตั้งรหัสผ่าน
6. ในฐานะผู้ใช้ที่สมัครด้วย Google ฉันต้องการให้ระบบตั้งชื่อผู้ใช้จากชื่อบัญชี Google เพื่อจะได้ไม่ต้องกรอกเพิ่ม
7. ในฐานะผู้ใช้ที่บัญชี Google ไม่มีชื่อ ฉันต้องการให้ระบบใช้ส่วนหน้า @ ของอีเมลเป็นชื่อผู้ใช้ เพื่อให้มีชื่อแสดงเสมอ
8. ในฐานะผู้ใช้ที่มีชื่อผู้ใช้อยู่แล้ว ฉันต้องการให้การ login ด้วย Google ไม่เขียนทับชื่อเดิม เพื่อให้ชื่อที่ตั้งไว้ยังอยู่
9. ในฐานะผู้ใช้ที่สมัครด้วยรหัสผ่าน ฉันต้องการกด login ด้วย Google ที่อีเมลเดียวกันแล้วเข้าบัญชีผู้ใช้เดิม เพื่อให้เห็นข้อมูลการเงินชุดเดิม
10. ในฐานะผู้ใช้ ฉันต้องการเห็นปุ่ม Google ทั้งในแท็บเข้าสู่ระบบและแท็บสมัคร โดยทำงานเหมือนกัน เพื่อจะได้ไม่ต้องคิดว่าต้องกดแท็บไหน
11. ในฐานะผู้ใช้ web ฉันต้องการให้ login ด้วย Google แล้วกลับเข้ามาในแอปเว็บที่เดิม เพื่อใช้งานต่อได้ทันที
12. ในฐานะผู้ใช้ที่กดยกเลิกหน้าเลือกบัญชี Google ฉันต้องการกลับมาหน้า login โดยไม่มี error ที่ทำให้ตกใจ
13. ในฐานะผู้ใช้ที่ login ด้วย Google ไม่สำเร็จ เช่น เน็ตหลุด ฉันต้องการเห็นข้อความภาษาไทยที่เข้าใจได้
14. ในฐานะผู้ใช้ใหม่ที่สมัครด้วยรหัสผ่าน ฉันต้องการรับรหัส OTP ทางอีเมลแล้วกรอกในแอป เพื่อยืนยันว่าเป็นเจ้าของอีเมล
15. ในฐานะผู้ใช้ที่ไม่ได้รับรหัส OTP สำหรับสมัคร ฉันต้องการขอรหัสใหม่ได้ เพื่อจะได้สมัครให้เสร็จ
16. ในฐานะผู้ใช้ที่กรอก OTP ผิดหรือรหัสหมดอายุ ฉันต้องการเห็นข้อความบอกและขอรหัสใหม่ได้
17. ในฐานะผู้ใช้ที่สมัครไว้แต่ยังไม่ได้ยืนยันอีเมล ฉันต้องการให้หน้า login พาไปยืนยันอีเมลได้ เพื่อจะไม่ติดค้าง
18. ในฐานะผู้ใช้ที่สมัครด้วยอีเมลที่มีบัญชีผู้ใช้อยู่แล้ว ฉันต้องการเห็นข้อความว่าอีเมลนี้มีบัญชีผู้ใช้แล้ว และให้ลองเข้าด้วยรหัสผ่านหรือ Google
19. ในฐานะเจ้าของอีเมล ฉันต้องการให้ข้อความตอนสมัครซ้ำไม่บอกว่าบัญชีผู้ใช้นั้นใช้ช่องทางไหน เพื่อไม่ให้คนอื่นรู้ข้อมูลบัญชีของฉัน
20. ในฐานะเจ้าของอีเมล ฉันต้องการให้คนอื่นสมัครด้วยอีเมลของฉันล่วงหน้าแล้วเข้าข้อมูลของฉันไม่ได้ เพื่อความปลอดภัยของข้อมูลการเงิน
21. ในฐานะผู้ใช้ที่มีรหัสผ่าน ฉันต้องการเปลี่ยนรหัสผ่านในหน้าตั้งค่า เพื่อจะได้ไม่ต้องใช้ flow ลืมรหัสผ่าน
22. ในฐานะผู้ใช้ที่เปลี่ยนรหัสผ่าน ฉันต้องการให้ระบบตรวจรหัสผ่านปัจจุบันก่อน เพื่อกันคนที่ได้เครื่องที่ login ค้างไว้มาเปลี่ยนรหัส
23. ในฐานะผู้ใช้ที่เปลี่ยนรหัสผ่าน ฉันต้องการกรอกรหัสใหม่สองครั้ง เพื่อกันพิมพ์ผิด
24. ในฐานะผู้ใช้ที่ตั้งรหัสใหม่ไม่ผ่านเงื่อนไข เช่น สั้นไป ซ้ำรหัสเดิม หรือเคยรั่วไหล ฉันต้องการเห็นเหตุผลเป็นภาษาไทย
25. ในฐานะผู้ใช้ที่เปลี่ยนรหัสผ่านแล้ว ฉันต้องการให้เครื่องอื่นยังไม่ถูก logout เพื่อไม่ต้อง login ใหม่ทุกเครื่อง
26. ในฐานะผู้ใช้ที่มีแค่ Google ฉันต้องการตั้งรหัสผ่านในหน้าตั้งค่าโดยไม่ต้องกรอกรหัสเดิม เพื่อให้ login ด้วยอีเมลและรหัสผ่านได้อีกทาง
27. ในฐานะผู้ใช้ที่มีแค่ Google และระบบต้องการให้ยืนยันตัวตนซ้ำก่อนตั้งรหัสผ่าน ฉันต้องการรับรหัสยืนยันทางอีเมลแล้วตั้งรหัสต่อได้ในขั้นตอนเดียวกัน
28. ในฐานะผู้ใช้ที่ตั้งรหัสผ่านแล้ว ฉันต้องการให้เมนูเปลี่ยนจาก "ตั้งรหัสผ่าน" เป็น "เปลี่ยนรหัสผ่าน" เพื่อให้รู้ว่าตอนนี้มีรหัสผ่านแล้ว
29. ในฐานะผู้ใช้ที่มีแค่ Google ฉันต้องการใช้ "ลืมรหัสผ่าน" เพื่อสร้างรหัสผ่านได้ด้วย
30. ในฐานะผู้ใช้ ฉันต้องการเห็นกลุ่ม "ช่องทางเข้าสู่ระบบ" ในหน้าตั้งค่า เพื่อรู้ว่าบัญชีผู้ใช้ของฉันเข้าได้ทางไหนบ้าง
31. ในฐานะผู้ใช้ที่เชื่อม Google แล้ว ฉันต้องการเห็นอีเมล Google ที่เชื่อมอยู่
32. ในฐานะผู้ใช้ที่สมัครด้วยรหัสผ่าน ฉันต้องการเชื่อม Google ในหน้าตั้งค่า เพื่อครั้งหน้าจะ login ด้วย Google ได้
33. ในฐานะผู้ใช้ที่เลือก Google ที่อีเมลไม่ตรงกับบัญชีผู้ใช้ ฉันต้องการเห็นข้อความว่าต้องใช้ Google ที่อีเมลตรงกัน
34. ในฐานะผู้ใช้ที่เลือก Google ที่ผูกกับบัญชีผู้ใช้อื่นอยู่แล้ว ฉันต้องการเห็นข้อความว่าบัญชี Google นี้ถูกใช้กับบัญชีผู้ใช้อื่นแล้ว
35. ในฐานะผู้ใช้ web ฉันต้องการเชื่อม Google แล้วกลับมาที่หน้าตั้งค่าโดยเห็นว่าเชื่อมสำเร็จ
36. ในฐานะผู้ใช้ที่มีทั้งรหัสผ่านและ Google ฉันต้องการยกเลิกการเชื่อม Google ได้ เมื่อไม่อยากใช้ช่องทางนี้แล้ว
37. ในฐานะผู้ใช้ ฉันต้องการให้ระบบถามยืนยันก่อนยกเลิกการเชื่อม Google เพื่อกันกดพลาด
38. ในฐานะผู้ใช้ที่มีช่องทางเข้าสู่ระบบช่องทางเดียว ฉันต้องการไม่เห็นปุ่มยกเลิกการเชื่อม เพื่อจะไม่ทำให้ตัวเองเข้าบัญชีผู้ใช้ไม่ได้
39. ในฐานะผู้ใช้ที่ login ด้วย Google แล้ว ฉันต้องการให้ logout ล้างการเลือกบัญชี Google ด้วย เพื่อครั้งหน้าจะเลือกบัญชี Google อื่นได้
40. ในฐานะผู้ใช้ที่ลบบัญชีผู้ใช้ ฉันต้องการให้แอปล้างการเชื่อม Google ในเครื่องด้วย เพื่อไม่ให้เหลือสถานะค้าง
41. ในฐานะนักพัฒนา ฉันต้องการเก็บ Google Client ID ในไฟล์ config ของแต่ละ env เพื่อไม่ต้อง hard-code และแยก dev กับ prod ได้
42. ในฐานะนักพัฒนา ฉันต้องการให้ปุ่ม Google ถูกซ่อนเมื่อ env ไม่ได้ตั้ง Client ID ไว้ เพื่อให้รันแอปได้แม้ยังไม่ได้ setup Google
43. ในฐานะนักพัฒนา ฉันต้องการคู่มือ setup Google Cloud และ Supabase แบบทีละขั้น เพื่อเปิด env ใหม่ได้โดยไม่ต้องเดา

## Implementation Decisions

**โมเดลบัญชีผู้ใช้** (ตาม ADR 0002)
- อีเมลหนึ่งมีบัญชีผู้ใช้ได้บัญชีเดียว โดยใช้ automatic identity linking ของ Supabase
- เปิด Confirm email ใน Supabase เพื่อให้การเชื่อมช่องทางอัตโนมัติปลอดภัย
- Manual linking อนุญาตเฉพาะ Google ที่อีเมลตรงกับอีเมลหลักของบัญชีผู้ใช้ (เทียบแบบไม่สนตัวพิมพ์เล็ก/ใหญ่) ถ้าไม่ตรงให้ปฏิเสธก่อนเรียก link

**AuthProvider** (จุดเชื่อมหลักระหว่าง UI กับ Supabase Auth) ขยายดังนี้
- `signInWithGoogle()`
  - Android/iOS: ใช้ `google_sign_in` ขอ idToken และ accessToken แล้วเรียก `signInWithIdToken(provider: google)`
  - Web: ใช้ `signInWithOAuth(google)` โดยให้ `redirectTo` เป็น origin ปัจจุบัน
  - ถ้าผู้ใช้กดยกเลิก ให้คืนค่า false โดยไม่ตั้ง error
- เมื่อ signedIn แล้วยังไม่มี `username` ใน metadata ให้ตั้งจาก `full_name` หรือ `name` ของ Google ถ้าไม่มีทั้งสองค่า ใช้ส่วนหน้า @ ของอีเมล
- `signUp()` เปลี่ยนพฤติกรรม
  - ไม่ signOut หลังสมัครแล้ว แต่คืนสถานะว่า "ต้องยืนยันอีเมล"
  - ถ้า response ได้ user ที่ `identities` เป็นค่าว่าง หรือได้ error `User already registered` ให้ตั้ง error กลาง ๆ ว่าอีเมลนี้มีบัญชีผู้ใช้แล้ว
- `verifySignUpCode(email, code)` ใช้ `verifyOTP(type: signup)` เมื่อสำเร็จให้ถือว่าเข้าสู่ระบบแล้ว และ `resendSignUpCode(email)` ใช้ `resend(type: signup)`
- signIn ที่ได้ error `Email not confirmed` ให้ UI พาไปขั้นตอนกรอก OTP ยืนยันอีเมลได้
- `changePassword(currentPassword, newPassword)` ตรวจรหัสเดิมด้วย `signInWithPassword` ด้วยอีเมลของ user ปัจจุบันก่อน แล้วจึง `updateUser(password)`
- `setPassword(newPassword, {nonce})` ใช้กับคนที่มีแค่ Google ถ้า Supabase ตอบว่าต้อง reauthenticate (เพราะเปิด Secure password change ไว้) ให้เรียก `reauthenticate()` เพื่อส่งรหัสทางอีเมล แล้วให้ UI ขอรหัสนั้นมาเรียกซ้ำพร้อม nonce
- `hasPassword` เป็น state ที่โหลดจาก RPC `has_password()` ตอน init, ตอน signedIn และหลังตั้งหรือเปลี่ยนรหัสผ่านสำเร็จ
- `linkedGoogleIdentity` และ `canUnlinkGoogle` (มี identity ตั้งแต่ 2 ตัว) อ่านจาก `user.identities`
- `linkGoogle()`
  - มือถือ: `google_sign_in` แล้ว `linkIdentityWithIdToken` โดยตรวจอีเมลจาก Google ก่อน
  - Web: `linkIdentity(google)` แบบ redirect แล้วตรวจอีเมลหลังกลับมา ถ้าไม่ตรงให้ unlink ทันทีและแจ้ง error
  - ถ้าได้ error ว่า identity ผูกกับบัญชีผู้ใช้อื่นแล้ว ให้แสดงข้อความตามที่กำหนด
- `unlinkGoogle()` ใช้ `unlinkIdentity` และเรียก `GoogleSignIn.signOut()` ต่อจากนั้น
- `signOut()` และ `deleteAccount()` เรียก `GoogleSignIn.signOut()` ด้วยบนมือถือ
- ฟัง `AuthChangeEvent.userUpdated` เพื่ออัปเดต user และ identities หลังเชื่อมหรือยกเลิกการเชื่อม
- เพิ่ม mapping error ภาษาไทยใน `_getErrorMessage` ให้ครอบคลุม error ใหม่ทั้งหมด

**Database**
- migration ใหม่สร้าง function `public.has_password()` แบบ `security definer` และ `stable` คืน boolean ว่า `auth.users.encrypted_password` ของ `auth.uid()` ไม่เป็น null และไม่ว่าง
- `GRANT EXECUTE` ให้ `authenticated` และ revoke จาก `anon`/`public`
- ไม่มีตารางใหม่

**Config**
- เพิ่ม key `GOOGLE_WEB_CLIENT_ID` (ใช้เป็น serverClientId บนมือถือด้วย) และ `GOOGLE_IOS_CLIENT_ID` ใน config ของแต่ละ env และไฟล์ example
- ถ้าค่าว่าง ไม่แสดง UI ของ Google ทั้งในหน้า login และหน้าตั้งค่า
- iOS ต้องใส่ reversed client ID เป็น URL scheme ใน Info.plist ของแต่ละ flavor ส่วน Android ไม่ต้องแก้ manifest

**Platform**
- รองรับ Android, iOS และ Web
- desktop ไม่อยู่ใน scope จึงซ่อน UI ของ Google ทั้งหมด

**UI** (ทำตาม `docs/design.md`)
- ปุ่ม Google แยกเป็น widget ของ module auth ตั้งชื่อตามกติกา prefix feature วางใต้ฟอร์มพร้อมเส้นคั่น "หรือ" ทั้งสองแท็บ
- ขั้นตอนกรอก OTP ยืนยันอีเมลตอนสมัครแยกเป็นไฟล์ของตัวเองใน module auth โดยใช้รูปแบบเดียวกับหน้า reset password
- เพิ่ม `AutofillGroup` และ hints ดังนี้
  - login: email, password
  - สมัคร: email, newPassword, username
  - เปลี่ยนรหัส: password, newPassword
  - OTP: oneTimeCode
- เรียก `TextInput.finishAutofillContext()` เมื่อ login, สมัคร หรือเปลี่ยนรหัสสำเร็จ
- เพิ่มกลุ่ม "ช่องทางเข้าสู่ระบบ" ในส่วนบัญชีผู้ใช้ของหน้าตั้งค่า มีสองแถว
  - รหัสผ่าน: แสดง "เปลี่ยนรหัสผ่าน" หรือ "ตั้งรหัสผ่าน" ตาม `hasPassword`
  - Google: ถ้าเชื่อมแล้วแสดงอีเมล Google และปุ่มยกเลิกการเชื่อม (เฉพาะเมื่อ `canUnlinkGoogle`) ถ้ายังไม่เชื่อมแสดงปุ่ม "เชื่อม Google"
- form เปลี่ยนรหัสและตั้งรหัสเป็น bottom sheet หรือ dialog ตาม pattern ของ settings sheets ที่มีอยู่
- การยกเลิกการเชื่อมต้องมี confirm dialog
- หน้า auth ต้องไม่เกิน 800 บรรทัด ให้แยก widget ออกตามกติกาใน AGENTS.md

**เอกสาร** (ทำหลังจบงาน)
- สร้างคู่มือ setup Google Auth ใน `docs/setup` ครอบคลุมเรื่องต่อไปนี้
  - การสร้าง OAuth client แบบ Web, Android (SHA-1 ของ debug และ release ต่อ flavor) และ iOS แยกกันสำหรับ dev และ prod
  - การใส่ Client ID และ Secret ใน Supabase Google provider และเปิด "Skip nonce check" ถ้าจำเป็นสำหรับ iOS
  - การเปิด Allow manual linking
  - การเพิ่ม Redirect URLs สำหรับ web
  - การใส่ key ใน config และ URL scheme ของ iOS
- อัปเดตคู่มือ Supabase setup ดังนี้
  - เปิด Confirm email
  - template "Confirm signup" ต้องแสดง `{{ .Token }}`
  - template "Reauthentication" ต้องแสดง `{{ .Token }}`
  - Secure password change
- อัปเดต README ให้ลิงก์ไปคู่มือใหม่

## Testing Decisions

- ตาม AGENTS.md ไม่เขียน unit test ใหม่ เว้นแต่ผู้ใช้สั่ง
- จุดที่จะทดสอบ (seam) มีจุดเดียวคือ public API ของ `AuthProvider` ให้ทดสอบด้วยมือบน Supabase dev project จริง
- กรณีที่ต้องผ่าน
  1. สมัครด้วยรหัสผ่าน → ได้ OTP → ยืนยัน → เข้าระบบ
  2. สมัครซ้ำด้วยอีเมลที่มีบัญชีผู้ใช้อยู่แล้ว → ขึ้นข้อความกลาง ๆ
  3. สมัครด้วยรหัสผ่าน แล้ว login ด้วย Google ที่อีเมลเดียวกัน → เข้าบัญชีผู้ใช้เดิม ข้อมูลเดิมอยู่ครบ
  4. สมัครด้วย Google → ได้ username อัตโนมัติ → ตั้งรหัสผ่าน (รวมขั้นตอน reauthenticate ถ้า Supabase ขอ) → logout → login ด้วยรหัสผ่านได้
  5. สมัครด้วย Google แล้วตั้งรหัสผ่าน → ตรวจว่า identities มีกี่ตัว และปุ่มยกเลิกการเชื่อมแสดงตามจริง
  6. ผู้ใช้ที่สมัครด้วยรหัสผ่านเชื่อม Google ที่อีเมลตรง → สำเร็จ, อีเมลไม่ตรง → ถูกปฏิเสธ, Google ที่ผูกบัญชีผู้ใช้อื่นอยู่ → error
  7. ยกเลิกการเชื่อม Google แล้ว login ด้วยรหัสผ่านยังได้
  8. เปลี่ยนรหัสผ่านโดยกรอกรหัสเดิมผิด → ถูกปฏิเสธ
  9. password manager บันทึกและเติมรหัสได้บน Android, iOS และ Web
- ถ้าจะเขียน test ภายหลัง ให้ดู `test/sync_provider_test.dart` เป็นตัวอย่างการทดสอบ provider

## Out of Scope

- Google login บน desktop (macOS, Windows, Linux)
- Sign in with Apple และ provider อื่น
- iOS Associated Domains / Android Digital Asset Links สำหรับ shared credentials กับเว็บ
- การเปลี่ยนอีเมลหลักของบัญชีผู้ใช้
- การ logout ทุกเครื่องหลังเปลี่ยนรหัสผ่าน
- การรวมบัญชีผู้ใช้สองบัญชีที่สร้างแยกกันไว้แล้ว
- MFA

## Further Notes

- คู่มือ Supabase setup ที่มีอยู่แนะนำให้เปิด Secure password change ไว้ จึงน่าจะต้องทำขั้นตอน reauthenticate ตอน "ตั้งรหัสผ่าน" ส่วน "เปลี่ยนรหัสผ่าน" น่าจะไม่ต้อง เพราะการตรวจรหัสเดิมด้วย signInWithPassword ทำให้ session ใหม่อยู่แล้ว
- ต้องตรวจกับ Supabase จริงว่าคนที่สมัครด้วย Google แล้วตั้งรหัสผ่านได้ identity `email` เพิ่มหรือไม่ ถ้าไม่ได้ คนกลุ่มนี้จะยกเลิกการเชื่อม Google ไม่ได้ ซึ่งเป็นไปตามที่ตั้งใจ
- ผู้ใช้เดิมที่สมัครตอนปิด Confirm email ถือว่ายืนยันอีเมลแล้วในระบบ ไม่ต้องทำ migration ใด ๆ
- ตรวจ version ของ `supabase_flutter` ให้รองรับ `linkIdentityWithIdToken` ถ้ายังไม่รองรับให้ upgrade
